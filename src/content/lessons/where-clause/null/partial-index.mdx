Oracle's peculiar handling of NULL in indexes can be turned into something useful: a partial index. All it takes is to make the indexed value NULL for every row that should not be in the index.

## 1. The index to emulate

The target is the queue index from the [partial index page](/sql/where-clause/partial-and-filtered-indexes/):

```sql
CREATE INDEX messages_todo
          ON messages (receiver)
       WHERE processed = 'N'
```

## 2. A function that returns NULL for unwanted rows

The building block is a function whose result is the `RECEIVER` value for unprocessed messages and NULL for everything else:

```sql
CREATE OR REPLACE
FUNCTION pi_processed(processed CHAR, receiver NUMBER)
RETURN NUMBER
DETERMINISTIC
AS BEGIN
   IF processed IN ('N') THEN
      RETURN receiver;
   ELSE
      RETURN NULL;
   END IF;
END
```

The function must be declared [deterministic](/sql/where-clause/functions/user-defined-functions/), as any function used in an index definition must.

## 3. The index and the query

Now the index contains only the rows with `PROCESSED = 'N'`, because for every other row the indexed value is NULL and Oracle writes no entry:

```sql
CREATE INDEX messages_todo
          ON messages (pi_processed(processed, receiver))
```

To use it, the query must contain the indexed expression:

```sql
SELECT message
  FROM messages
 WHERE pi_processed(processed, receiver) = ?
```

<KeyIdea>The optimizer matches a function-based index by its expression. A query written as `processed = 'N' AND receiver = ?` does not use this index, even though it asks for exactly the indexed rows.</KeyIdea>

<Callout kind="warning" title="Common mistake">Adding a second, never-NULL column to the function-based index for sorting or covering. As soon as one indexed column has a value, the row gets an entry, and the index is a full index again. Keep every column inside the function, or keep the index to the one expression.</Callout>

## 4. Partial indexes, part II

Oracle has a second route, which works at the partition level. Since release 12c a partitioned table can switch indexing off for individual partitions (`ALTER TABLE ... MODIFY PARTITION ... INDEXING OFF`), and an index created with `INDEXING PARTIAL` simply has no entries for those partitions:

```sql
CREATE INDEX messages_todo
          ON messages (receiver)
     INDEXING PARTIAL
```

Which rows stay out is decided by the partition key, so this helps only when the unwanted rows live in partitions of their own, for instance messages partitioned by `PROCESSED`. Before 12c the same effect took a trick no less unsettling than the NULL route: partition the index, make the partition for the unwanted rows deliberately unusable, and set `SKIP_UNUSABLE_INDEXES` so that queries ignore the broken partition instead of failing. For a condition on arbitrary rows, the function-based index above remains the only way.
