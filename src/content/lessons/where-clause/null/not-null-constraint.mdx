The previous lesson ended with a rule: to index an `IS NULL` condition in Oracle, the index must contain a column that can never be NULL. This lesson is about the word *never*. It is not enough that no NULL happens to be stored. The database has to be certain that none can ever be stored; otherwise it must assume that the index is missing some of the table's rows.

## 1. Constraints, not contents

Pair `DATE_OF_BIRTH` with `LAST_NAME` in the index:

```sql
DROP INDEX emp_dob
```

```sql
CREATE INDEX emp_dob_name
          ON employees (date_of_birth, last_name)
```

```sql
SELECT *
  FROM employees
 WHERE date_of_birth IS NULL
```

The query uses the index only while `LAST_NAME` carries a `NOT NULL` constraint. Remove it, and the index becomes unusable for this query, although not a single row has changed:

```sql
ALTER TABLE employees MODIFY last_name NULL
```

```sql
SELECT *
  FROM employees
 WHERE date_of_birth IS NULL
```

Without the constraint, a row with both columns NULL is possible, and such a row would have no index entry. The optimizer cannot rule it out, so it reads the table.

<KeyIdea title="Tip">Without a NOT NULL constraint, Oracle may refuse an index that in fact holds every row. `count(*)` queries suffer first, because the database likes to answer them from the smallest index that is guaranteed to contain every row.</KeyIdea>

Constant expressions, like the `'X'` in the [previous lesson](/sql/where-clause/null/index/), are also known to be never NULL.

## 2. A user-defined function hides the constraint

An index on a user-defined function does not carry a `NOT NULL` property, even when the function obviously never returns NULL:

```sql
CREATE OR REPLACE FUNCTION blackbox(id IN NUMBER) RETURN NUMBER
DETERMINISTIC
IS BEGIN
   RETURN id;
END
```

```sql
DROP INDEX emp_dob_name
```

```sql
CREATE INDEX emp_dob_bb
          ON employees (date_of_birth, blackbox(employee_id))
```

```sql
SELECT *
  FROM employees
 WHERE date_of_birth IS NULL
```

```
----------------------------------------------------
| Id | Operation         | Name      | Rows | Cost |
----------------------------------------------------
|  0 | SELECT STATEMENT  |           |    1 |  477 |
|* 1 |  TABLE ACCESS FULL| EMPLOYEES |    1 |  477 |
----------------------------------------------------
```

The name says it: the function is a black box to the optimizer, just as in [Case-Insensitive Search](/sql/where-clause/functions/case-insensitive-search/). We can read that it passes its argument straight through; the database only sees a function that returns a number. The `NOT NULL` property of `EMPLOYEE_ID` does not survive the call. The index does in fact contain every row, but the optimizer cannot know that, so it does not use it.

## 3. Telling the optimizer in the query

If you know that the function never returns NULL, say so in the where clause:

```sql
SELECT *
  FROM employees
 WHERE date_of_birth IS NULL
   AND blackbox(employee_id) IS NOT NULL
```

```
-------------------------------------------------------------
|Id |Operation                   | Name       | Rows | Cost |
-------------------------------------------------------------
| 0 |SELECT STATEMENT            |            |    1 |    3 |
| 1 | TABLE ACCESS BY INDEX ROWID| EMPLOYEES  |    1 |    3 |
|*2 |  INDEX RANGE SCAN          | EMP_DOB_BB |    1 |    2 |
-------------------------------------------------------------
```

The added condition is always true and changes nothing in the result. But it restricts the query to rows that, by the definition of the index, must have an entry, and Oracle recognises that.

## 4. A virtual column with its own constraint

There is no way to declare that a function never returns NULL. What you can do, since Oracle 11g, is move the call into a virtual column and give that column a `NOT NULL` constraint:

```sql
ALTER TABLE employees ADD bb_expression
       GENERATED ALWAYS AS (blackbox(employee_id)) NOT NULL
```

```sql
DROP   INDEX emp_dob_bb
```

```sql
CREATE INDEX emp_dob_bb
          ON employees (date_of_birth, bb_expression)
```

```sql
SELECT *
  FROM employees
 WHERE date_of_birth IS NULL
   AND blackbox(employee_id) IS NOT NULL
```

```
-------------------------------------------------------------
|Id |Operation                   | Name       | Rows | Cost |
-------------------------------------------------------------
| 0 |SELECT STATEMENT            |            |    1 |    3 |
| 1 | TABLE ACCESS BY INDEX ROWID| EMPLOYEES  |    1 |    3 |
|*2 |  INDEX RANGE SCAN          | EMP_DOB_BB |    1 |    2 |
-------------------------------------------------------------
```

The constraint now lives on the column the index is built on, and the proof is back.

## 5. Built-in functions keep the property

Oracle knows that some of its own functions return NULL only when given NULL. `UPPER` is one of them:

```sql
DROP INDEX emp_dob_bb
```

```sql
CREATE INDEX emp_dob_upname
          ON employees (date_of_birth, upper(last_name))
```

```sql
SELECT *
  FROM employees
 WHERE date_of_birth IS NULL
```

```
----------------------------------------------------------
|Id |Operation                   | Name           | Cost |
----------------------------------------------------------
| 0 |SELECT STATEMENT            |                |    3 |
| 1 | TABLE ACCESS BY INDEX ROWID| EMPLOYEES      |    3 |
|*2 |  INDEX RANGE SCAN          | EMP_DOB_UPNAME |    2 |
----------------------------------------------------------
```

`UPPER` passes the `NOT NULL` property of `LAST_NAME` through. Drop the constraint on the column, and the index is useless again:

```sql
ALTER TABLE employees MODIFY last_name NULL
```

```sql
SELECT *
  FROM employees
 WHERE date_of_birth IS NULL
```

```
----------------------------------------------------
| Id | Operation         | Name      | Rows | Cost |
----------------------------------------------------
|  0 | SELECT STATEMENT  |           |    1 |  477 |
|* 1 |  TABLE ACCESS FULL| EMPLOYEES |    1 |  477 |
----------------------------------------------------
```

<Callout kind="warning" title="Common mistake">Dropping a NOT NULL constraint "because the application checks it anyway". In Oracle that can silently turn IS NULL lookups and count(*) queries into full table scans, with no change to any query. Declare every column that must have a value as NOT NULL; it costs nothing and gives every optimizer a fact it cannot discover on its own.</Callout>
