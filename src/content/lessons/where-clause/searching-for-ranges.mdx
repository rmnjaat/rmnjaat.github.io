Every example so far compared a column with one value. Real where clauses ask for the sales of last month, the employees born in the seventies, the names that start with "Win". A B-tree answers those as well, because its leaf nodes are sorted: the tree traversal finds the first entry inside the range, and the leaf chain delivers the rest.

## 1. Ranges use the index like equality does

The operators `<`, `>`, `<=`, `>=` and `BETWEEN` all become an index range scan with a start point, an end point, or both. A `LIKE` pattern can do the same, provided the pattern leaves the index something to start from.

## 2. What changes

With equality the scanned part of the index is as narrow as the data allows. With a range the scan is as wide as the range. If the columns of a concatenated index are in the wrong order it is wider still, and most of what the scan reads is thrown away.

That is why range operators limit the choice of column order in a multi-column index. For some queries the limit rules out every good option: there are where clauses for which no "correct" column order exists.

<KeyIdea>Range operators use the index as readily as equality does, and they decide the column order of a concatenated index.</KeyIdea>
