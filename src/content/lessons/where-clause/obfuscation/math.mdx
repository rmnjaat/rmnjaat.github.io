One more class of obfuscation is smart in the same way as the previous one, but it uses a calculation instead of a logical expression.

## 1. Two questions

Can this statement use an index on `NUMERIC_NUMBER`?

```sql
SELECT numeric_number
  FROM table_name
 WHERE numeric_number - 1000 > ?
```

And can this one use an index on `A` and `B`, in whichever order you like?

```sql
SELECT a, b
  FROM table_name
 WHERE 3*a + 5 = b
```

Think of it from the vendor's side: an optimizer that rearranges equations would be a lot of work for a rare benefit, and no mainstream database does it. Neither statement uses the index; the expression is evaluated as written, row by row.

## 2. Switching an index off with zero

Math also works as a deliberate obfuscation, like the one used [for the full-text LIKE](/sql/where-clause/obfuscation/concatenation/). Adding zero is enough:

```sql
SELECT numeric_number
  FROM table_name
 WHERE numeric_number + 0 = ?
```

The value is unchanged, the column is hidden, and the index is out of play. It also means that `+ 0` or `* 1` in a slow query is rarely a typo. Someone switched the index off, possibly for a reason that no longer holds.

## 3. Rearranging the equation

The expressions can still be indexed with a [function-based index](/sql/where-clause/functions/), if you treat the where clause like an equation and move things around. Put the table references on one side and the constants on the other:

```sql
SELECT a, b
  FROM table_name
 WHERE 3*a - b = -5
```

Then index the left-hand side:

```sql
CREATE INDEX math ON table_name (3*a - b)
```

The query uses exactly the indexed expression, compared with a constant, and the index serves it as an equality lookup.

<KeyIdea>Isolate the column, or isolate an expression you can index. What the database will not do is work out either form from the other.</KeyIdea>

<Callout kind="warning" title="Common mistake">Relying on the optimizer to simplify `col - 1000 > ?` into `col > ? + 1000`. It will not. Either move the arithmetic to the parameter side yourself, in the SQL or in the application, or index the expression as written.</Callout>
