  - An update touches only the indexes whose columns change.

<Check

  question="Why do indexes slow down INSERT, DELETE and UPDATE?"
  options={[
    'Because the database has to re-sort the whole index after every change.',

  explain="An index contains only data that is also in the table. Whenever that data changes, every index holding a copy has to be changed as well, inside the same statement. No re-sort is needed; the B-tree absorbs each change locally, but it is still one tree operation per index per row."

<Check
  client:visible
  question="Which statement is the only one that cannot benefit from an index directly?"
  options={[
    'INSERT, because it has no where clause.',
    'DELETE, because it removes rows instead of reading them.',
    'UPDATE, because it changes the indexed values.',
  ]}
  answer={0}
  explain="DELETE and UPDATE both have a where clause that is planned like a SELECT's, so an index can make finding the rows faster. An INSERT has nothing to find; every index is pure maintenance cost for it."
/>

<Check
  client:visible
  question="What is the only event that makes a B-tree deeper?"
  options={[
    'Any leaf node split.',
    'A split that propagates all the way up and splits the root node.',
    'Creating a second index on the same table.',
  ]}
  answer={1}
  explain="A leaf split adds a reference to the branch node above. If that node is full it splits too, and so on upwards. Only when the root itself splits does the tree gain a layer. Every other split keeps the depth unchanged."
/>

<Check
  client:visible
  question="Which statement about TRUNCATE TABLE is true?"
  options={[
    'It uses the primary key index to find the rows quickly.',
    'It removes all rows in one step, commits implicitly in most engines (not PostgreSQL and SQL Server), and fires no triggers.',
    'It is just a faster spelling of DELETE with no side effects.',
  ]}
  answer={1}
  explain="TRUNCATE does not look for rows at all; it discards the table contents wholesale. That makes it very fast, but it is not a plain delete: most engines commit implicitly, PostgreSQL and SQL Server being the exceptions, and no row triggers run."
/>
