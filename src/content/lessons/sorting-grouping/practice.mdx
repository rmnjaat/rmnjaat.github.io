prereqs: "You should have read the three lessons of this unit. Each exercise assumes you know what SQLite's <code>USE TEMP B-TREE</code> line means."
outcomes:
  - Recognise a sort in a SQLite plan and remove it with a concatenated index
  - Build an index whose column directions match a mixed ORDER BY
  - Turn a GROUP BY into a pipelined, index-only scan
recap:
  - USE TEMP B-TREE FOR ORDER BY or FOR GROUP BY is SQLite's sort. A plan without it is pipelined.
  - Equality columns first, then the sort or group columns, and the sort goes away.
  - A mixed ORDER BY needs an index with the same mix of directions.
  - Adding the aggregated column to the index makes the group by both pipelined and index-only.

Each playground below starts with a fresh copy of the example schema, so an index you create in one exercise does not exist in the next. Read the plan after every run; the point of each exercise is a line that appears or disappears.

## Exercise 1: make the sort disappear

The query lists the sales of subsidiary 20 in date order. Without a suitable index SQLite scans the table and sorts, and the plan says `USE TEMP B-TREE FOR ORDER BY`. The result has 10,000 rows.

<TryIt id="6.p1" tasks={[
  { text: 'Run the query as given and find <code>USE TEMP B-TREE FOR ORDER BY</code> in the plan.', sql: 'subsidiary_id\\s*=\\s*20[\\s\\S]*order\\s+by\\s+sale_date', plan: 'TEMP B-TREE FOR ORDER BY' },
  { text: 'Create an index on <code>(subsidiary_id, sale_date)</code> and run the query again. The plan should be a single <code>SEARCH</code> line.', sql: 'create\\s+index[\\s\\S]*subsidiary_id\\s*,\\s*sale_date' },
  { text: 'Change <code>= 20</code> to <code>&gt; 10</code>. The index is still used, but the temp b-tree is back. Why?', sql: 'subsidiary_id\\s*>\\s*10', plan: 'TEMP B-TREE FOR ORDER BY' },
]} sql={`SELECT sale_date, eur_value
  FROM sales
 WHERE subsidiary_id = 20
 ORDER BY sale_date;`}>
  <Fragment slot="hints">
    <details class="hint"><summary>Hint for task 2</summary><div class="d">The equality column goes first so the subsidiary's entries are adjacent; the sort column goes next so those entries are in date order.</div></details>
    <details class="hint"><summary>Hint for task 3</summary><div class="d">The range covers subsidiaries 20 and 30. Inside it the entries are in date order per subsidiary, not overall.</div></details>
    <details class="hint"><summary>Show solution</summary><div class="d"><pre>CREATE INDEX sales&#95;sub&#95;date ON sales (subsidiary&#95;id, sale&#95;date);
SELECT sale&#95;date, eur&#95;value
  FROM sales
 WHERE subsidiary&#95;id = 20
 ORDER BY sale&#95;date;
-- plan: SEARCH sales USING INDEX sales&#95;sub&#95;date (subsidiary&#95;id=?)</pre></div></details>
  </Fragment>
</TryIt>

## Exercise 2: a mixed ASC/DESC order

Now the same rows, latest date first and, within a date, the cheapest sale first. The playground already has `sales_sub_date_val` on `(subsidiary_id, sale_date, eur_value)`, all ascending. That index covers the query, but it cannot deliver the mixed order: the plan says `USE TEMP B-TREE FOR LAST TERM OF ORDER BY`.

<TryIt id="6.p2" setup={`CREATE INDEX sales_sub_date_val ON sales (subsidiary_id, sale_date, eur_value);`} tasks={[
  { text: 'Run the query and find <code>USE TEMP B-TREE FOR LAST TERM OF ORDER BY</code>. The index is read backwards for the date, and the values within each date are sorted separately.', sql: 'sale_date\\s+desc\\s*,\\s*eur_value', plan: 'LAST TERM OF ORDER BY' },
  { text: 'Drop the index and create it again with <code>sale_date DESC</code> in the middle. Run the query: the plan is a covering index search with no temp b-tree.', sql: 'create\\s+index[\\s\\S]*sale_date\\s+desc\\s*,\\s*eur_value' },
  { text: 'With the new index in place, ask for <code>ORDER BY sale_date, eur_value DESC</code>, the mirror image. Still no temp b-tree.', sql: 'order\\s+by\\s+sale_date\\s*,\\s*eur_value\\s+desc', plan: '^(?![\\s\\S]*TEMP B-TREE)SEARCH' },
]} sql={`SELECT sale_date, eur_value
  FROM sales
 WHERE subsidiary_id = 20
 ORDER BY sale_date DESC, eur_value;`}>
  <Fragment slot="hints">
    <details class="hint"><summary>Hint for task 2</summary><div class="d">The mixed order needs the index to be defined with the same mix. Only one column has to change direction.</div></details>
    <details class="hint"><summary>Show solution</summary><div class="d"><pre>DROP INDEX sales&#95;sub&#95;date&#95;val;
CREATE INDEX sales&#95;sub&#95;date&#95;val ON sales (subsidiary&#95;id, sale&#95;date DESC, eur&#95;value);
SELECT sale&#95;date, eur&#95;value
  FROM sales
 WHERE subsidiary&#95;id = 20
 ORDER BY sale&#95;date DESC, eur&#95;value;
-- plan: SEARCH sales USING COVERING INDEX sales&#95;sub&#95;date&#95;val (subsidiary&#95;id=?)</pre></div></details>
  </Fragment>
</TryIt>

## Exercise 3: a pipelined, index-only GROUP BY

Revenue per product for one day. Without an index SQLite scans the table and sorts the groups. The goal is a plan that reads one index range and touches neither the table nor a temp b-tree. The result has 15 groups.

<TryIt id="6.p3" tasks={[
  { text: 'Run the query and find <code>USE TEMP B-TREE FOR GROUP BY</code>.', sql: 'group\\s+by\\s+product_id', plan: 'TEMP B-TREE FOR GROUP BY' },
  { text: 'Create an index on <code>(sale_date, product_id)</code> and run again. The temp b-tree is gone, but the plan says <code>USING INDEX</code>, not <code>COVERING INDEX</code>: the table is still read for <code>eur_value</code>.', sql: 'create\\s+index[\\s\\S]*sale_date\\s*,\\s*product_id\\s*\\)' },
  { text: 'Create a second index on <code>(sale_date, product_id, eur_value)</code> and run once more. Now the plan says <code>USING COVERING INDEX</code>.', sql: 'create\\s+index[\\s\\S]*sale_date\\s*,\\s*product_id\\s*,\\s*eur_value' },
]} sql={`SELECT product_id, sum(eur_value)
  FROM sales
 WHERE sale_date = '2024-03-05'
 GROUP BY product_id;`}>
  <Fragment slot="hints">
    <details class="hint"><summary>Hint for task 3</summary><div class="d">A covering index holds every column the query touches: the where column, the group column and the aggregated column.</div></details>
    <details class="hint"><summary>Show solution</summary><div class="d"><pre>CREATE INDEX sales&#95;dt&#95;pr&#95;val ON sales (sale&#95;date, product&#95;id, eur&#95;value);
SELECT product&#95;id, sum(eur&#95;value)
  FROM sales
 WHERE sale&#95;date = '2024-03-05'
 GROUP BY product&#95;id;
-- plan: SEARCH sales USING COVERING INDEX sales&#95;dt&#95;pr&#95;val (sale&#95;date=?)</pre></div></details>
  </Fragment>
</TryIt>
