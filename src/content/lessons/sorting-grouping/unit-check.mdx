summary: Five multiple-choice questions covering the third power of indexing, the where clause interaction, ASC/DESC indexes, NULLS FIRST/LAST support and the two GROUP BY algorithms.
recap:
  - An index in ORDER BY order removes the sort and makes the execution pipelined.
  - Only the scanned range has to be in order; a range condition ahead of the sort column breaks it.
  - Mixed directions need a matching index definition; reversing all columns is a backward read.
  - GROUP BY has the same prerequisites as ORDER BY, minus ASC and DESC.

<Check
  client:visible
  question="The index is sales (sale_date, product_id). Which query can run without a sort operation?"
  options={[
    'WHERE sale_date = :d ORDER BY product_id',
    'WHERE sale_date >= :d ORDER BY product_id',
    'WHERE product_id = 7 ORDER BY sale_date',
  ]}
  answer={0}
  explain="With an equality on the leading column the scanned range is a single day, and within that day the entries are in product order. The range in the second query spans several days, each in its own product order. The third query cannot use the index for its where clause at all, because product_id is not the leading column."
/>

<Check
  client:visible
  question="When do ASC and DESC in a CREATE INDEX statement make a difference?"
  options={[
    'Whenever the query uses ORDER BY ... DESC.',
    'Only when one ORDER BY mixes ascending and descending columns.',
    'Never; every database ignores them.',
  ]}
  answer={1}
  explain="An index can be read in either direction, so reversing all columns needs no special index. Only a mixed order, such as sale_date ASC, product_id DESC, needs the index defined with the same mix. MySQL before 8.0 ignored the modifiers, but that is a limitation, not the rule."
/>

<Check
  client:visible
  question="Which database can build an index with an explicit NULLS FIRST or NULLS LAST placement, so that a query with that modifier gets a pipelined ORDER BY?"
  options={[
    'Oracle',
    'SQL Server',
    'PostgreSQL',
  ]}
  answer={2}
  explain="PostgreSQL accepts NULLS FIRST and NULLS LAST both in the ORDER BY and in the index definition (since 8.3). Oracle accepts the modifier in queries but not in indexes as of 23ai. SQL Server 2022 and MySQL 8.4 do not implement the modifier at all."
/>

<Check

  options={[
