## Exercise 1: a LIMIT that stops early

Ten newest sales. Without an index SQLite sorts all 20,000 rows and the limit trims the output. With an index on `sale_date` the scan runs backwards and stops after ten entries.

  { text: 'Create an index on <code>sale_date</code> and run the query again. The plan is <code>SCAN sales USING INDEX</code> without a temp b-tree, and the time drops.', sql: 'create\\s+index[\\s\\S]*\\(\\s*sale_date\\s*\\)' },
  { text: 'Add <code>WHERE subsidiary_id = 20</code>. The index is still used, but now the scan walks past the other subsidiaries. Which index would fix that?', sql: 'subsidiary_id\\s*=\\s*20[\\s\\S]*limit' },
]} sql={`SELECT sale_id, sale_date, eur_value
  FROM sales
 ORDER BY sale_date DESC
 LIMIT 10;`}>

## Exercise 2: the cost of OFFSET

The playground has `sales_date_id` on `(sale_date, sale_id)`, so the order is pipelined. The only variable is how far the offset makes the scan walk before it starts returning rows.

<TryIt id="7.p2" setup={`CREATE INDEX sales_date_id ON sales (sale_date, sale_id);`} tasks={[
  { text: 'Run page 2 (<code>OFFSET 10</code>) and note the time.', sql: 'offset\\s+10\\b', plan: '^SCAN sales USING INDEX sales_date_id' },
  { text: 'Change it to <code>OFFSET 5000</code> and run it a few times. The plan is identical; the time is not.', sql: 'offset\\s+5000', plan: '^SCAN sales USING INDEX sales_date_id' },
  { text: 'Try <code>OFFSET 19000</code>. The last page of a long result is its most expensive one.', sql: 'offset\\s+19000' },
]} sql={`SELECT sale_id, sale_date, eur_value
  FROM sales
 ORDER BY sale_date DESC, sale_id DESC
 LIMIT 10 OFFSET 10;`}>
  <Fragment slot="hints">
    <details class="hint"><summary>Why does the plan not change?</summary><div class="d">An index knows where a value is, not where the 5,001st entry is. The scan always starts at the end of the index and counts.</div></details>
  </Fragment>
</TryIt>

## Exercise 3: seek with row values

Same index. Page 501 by offset ends with sale 11887 on 2025-04-24. Fetch page 502 without counting.

<TryIt id="7.p3" setup={`CREATE INDEX sales_date_id ON sales (sale_date, sale_id);`} tasks={[
  { text: "Replace the OFFSET with <code>WHERE (sale_date, sale_id) &lt; ('2025-04-24', 11887)</code> and <code>LIMIT 10</code>. The plan says <code>SEARCH ... (sale_date&lt;?)</code>.", sql: '\\(\\s*sale_date\\s*,\\s*sale_id\\s*\\)\\s*<\\s*\\(', plan: 'SEARCH sales USING INDEX sales_date_id \\(sale_date<\\?\\)' },
  { text: "Now seek on the date alone: <code>WHERE sale_date &lt; '2025-04-24'</code>. Compare the first row with the previous result. Which rows went missing?", sql: "where\\s+sale_date\\s*<\\s*'2025-04-24'", plan: 'SEARCH sales USING INDEX sales_date_id \\(sale_date<\\?\\)' },
  { text: "Go backwards: fetch the ten rows <em>before</em> the boundary with <code>&gt;</code> and an ascending ORDER BY.", sql: '\\(\\s*sale_date\\s*,\\s*sale_id\\s*\\)\\s*>\\s*\\([\\s\\S]*order\\s+by\\s+sale_date\\s*(asc)?\\s*,\\s*sale_id\\s*(asc)?\\s*limit' },
]} sql={`SELECT sale_id, sale_date, eur_value
  FROM sales
 ORDER BY sale_date DESC, sale_id DESC
 LIMIT 10 OFFSET 5010;`}>
  <Fragment slot="hints">
    <details class="hint"><summary>Hint for task 2</summary><div class="d">Every sale on 2025-04-24 with a sale_id below 11887 belongs to page 502, and the date-only boundary skips all of them.</div></details>
    <details class="hint"><summary>Show solution</summary><div class="d"><pre>SELECT sale&#95;id, sale&#95;date, eur&#95;value
  FROM sales
 WHERE (sale&#95;date, sale&#95;id) &lt; ('2025-04-24', 11887)
 ORDER BY sale&#95;date DESC, sale&#95;id DESC
 LIMIT 10;
-- backwards: the page before the boundary, in reverse
SELECT sale&#95;id, sale&#95;date, eur&#95;value
  FROM sales
 WHERE (sale&#95;date, sale&#95;id) &gt; ('2025-04-24', 11887)
 ORDER BY sale&#95;date, sale&#95;id
 LIMIT 10;</pre></div></details>
  </Fragment>
</TryIt>

## Exercise 4: a ROW_NUMBER page

Same index. The window function gets its order from the index, but SQLite numbers every row before the outer filter sees one.

<TryIt id="7.p4" setup={`CREATE INDEX sales_date_id ON sales (sale_date, sale_id);`} tasks={[
  { text: 'Run the query. Inside the co-routine the plan reads <code>SCAN sales USING INDEX sales_date_id</code>: no sort for the window.', sql: 'row_number\\s*\\(\\s*\\)\\s*over[\\s\\S]*rn\\s+between\\s+11\\s+and\\s+20', plan: 'SCAN sales USING INDEX sales_date_id' },
  { text: 'Change the filter to <code>rn BETWEEN 5001 AND 5010</code> and compare the time with the seek query from exercise 3. The window is still an offset in disguise.', sql: 'rn\\s+between\\s+5001\\s+and\\s+5010' },
]} sql={`SELECT sale_id, sale_date, eur_value
  FROM (SELECT sale_id, sale_date, eur_value,
               ROW_NUMBER() OVER (ORDER BY sale_date DESC, sale_id DESC) AS rn
          FROM sales) numbered
 WHERE rn BETWEEN 11 AND 20
 ORDER BY rn;`}>
  <Fragment slot="hints">
    <details class="hint"><summary>Hint for task 2</summary><div class="d">Add a seek condition inside the subquery, WHERE (sale_date, sale_id) &lt; ('2025-04-24', 11887), and renumber from 1 to get the best of both.</div></details>
  </Fragment>
</TryIt>
