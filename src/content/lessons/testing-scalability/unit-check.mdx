<Check
  client:visible
  question="Two Oracle plans both show INDEX RANGE SCAN with the same row estimate. In one, the predicate section says access(section=:A) and filter(id2=:B). What does that tell you?"
  options={[
    'The index is fragmented and needs a rebuild.',
    'Only section bounds the scan. Every entry in that section is read and id2 is checked on each, so the work grows with the size of the section.',
    'The id2 column is not in the index at all.',
  ]}
  answer={1}
  explain="A filter predicate on an index operation is applied to entries the scan already visited. It removes rows from the result, not work from the scan. The column is in the index but not in a position the tree can use. See Data volume."
/>

<Check
  client:visible
  question="From the plans alone you learn that section is an access predicate and id2 is a filter predicate on an index containing both. What must be true of the index definition?"
  options={[
    'It starts with section, and id2 is not the second column.',
    'It starts with id2.',
    'It has exactly two columns in either order.',
  ]}
  answer={0}
  explain="section must lead the index or it could not bound the scan. If id2 came second it could bound the scan too, so something else sits between them: in the original, scale_slow was (section, id1, id2). See Data volume."

<Check
  client:visible
  question="With the data volume fixed, a query's response time goes from one second to 32 seconds as 25 copies of it run concurrently, while a second query stays under two seconds. What distinguishes the two?"
  options={[
    'The first query returns more rows.',
    'The first query has a filter predicate and visits many more index entries than it returns; load makes every one of those reads more expensive.',
    'The first query uses an index and the second does not.',
  ]}
  answer={1}
  explain="Both used an index and returned the same count. Load multiplies the cost of every block touched, and a scan that is not bounded by access predicates touches far more blocks. See System load."
/>

<Check
