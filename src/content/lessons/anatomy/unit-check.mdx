<Check
  client:visible
  question="Why are leaf nodes connected as a doubly linked list rather than stored one after another in key order?"
  options={[
    'Because a linked list is faster to search than an array.',
    'So that an insert only changes one leaf and two links, instead of moving every entry that comes after it.',
    'Because the database cannot allocate contiguous disk space.',
  ]}
  answer={1}
  explain="The list separates logical order from physical position. A new leaf can go anywhere on disk and the links tie it into the sequence; nothing else moves. The list is not faster to search, which is why the tree exists. See The leaf nodes."
/>

<Check
  client:visible
  question="What does each entry in a branch node hold?"
  options={[
    'The smallest key of the child node and a pointer to it.',
    'The largest key of the child node and a pointer to it.',
    'A copy of every key in the child node.',
  ]}
  answer={1}
  explain="A branch entry stores the biggest key of the node below it. The lookup follows the first entry whose key is greater than or equal to the search key, which rules out every child that cannot contain it. See The B-tree."
/>

<Check
  client:visible
  question="A real index on a table with ten million rows typically has a depth of"
  options={[
    'about ten levels, one per million rows.',
    'three to five levels.',
    'about 23 levels, since 2 to the 23rd is eight million.',
  ]}
  answer={1}
  explain="A B-tree node holds hundreds of entries, so each level multiplies capacity by hundreds, not by two. Three to five levels cover anything from millions to hundreds of millions of entries; six is rare. The 23-level answer describes a binary tree, and balanced does not mean binary. See The B-tree."
/>

<Check
  client:visible
  question="Which of the three steps of an index lookup has an upper bound on the number of blocks it reads?"
  options={[
    'The tree traversal, bounded by the depth of the index.',
    'The leaf chain walk, bounded by the number of leaves.',
    'The table access, bounded by the number of table blocks.',
  ]}
  answer={0}
  explain="Only the traversal is bounded, by the depth. The chain walk grows with the number of matching entries and the table access runs once per match; both can touch any number of blocks, and they are what makes an index slow. See Slow indexes, part I."
/>
